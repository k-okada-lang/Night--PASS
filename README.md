[README_7.md](https://github.com/user-attachments/files/32332188/README_7.md)# Night PASS — キャバクラ・ラウンジ紹介サイト

キャバクラ・ラウンジ・クラブ・ガールズバー・スナック・コンカフェなど、ナイトワーク系のお店を検索できるお客様向けの紹介サイトです（「GOOD TABLE」飲食店紹介サイトを基に、業界向けに作り直したものです）。

キーワード検索、業態／人気エリアのアイコン検索、現在地からの距離順検索、店舗詳細（写真・営業時間・SNSリンク・地図・在籍キャスト紹介）、店舗情報を編集できる管理（アドミン）画面を備えています。

## ファイル構成

```
.
├── index.html   サイト本体（HTML／CSS／JavaScriptを1ファイルに統合）
└── README.md         このファイル
```

HTML・CSS・JavaScriptをすべて `index.html` 1ファイルにまとめてあります。他のファイルへの参照がないため、この1ファイルだけをコピーすればどこでもそのまま動きます。

## 使い方（ローカル確認）

`index.html` をブラウザで直接開くだけで動作します。サーバーは不要です。

## GitHub Pages で公開する場合

`index.html` という名前になっているため、GitHub の新規リポジトリにそのままアップロードするだけで公開できます。

1. GitHub で新しいリポジトリを作成する（Public にしてください）
2. リポジトリ画面の **Add file → Upload files** を開き、`index.html` と `README.md` をドラッグ＆ドロップしてアップロードし、**Commit changes**
3. リポジトリの **Settings → Pages** を開く
4. **Branch** を `main`（または該当ブランチ）、フォルダを `/ (root)` に設定して **Save**
5. 数分後、`https://ユーザー名.github.io/リポジトリ名/` で公開されます（`index.html` はルートで自動的に表示されるページなので、URLの末尾にファイル名を付ける必要はありません）

## 主な機能

- **検索**：キーワード／都道府県／エリア／業態の4項目で絞り込み、セット料金・新着・店名で並び替え。都道府県を選ぶと、エリアの選択肢がその都道府県に登録されているエリア（市町村区）だけに自動的に絞り込まれます（例：「宮城県」を選ぶと、宮城県内で登録した市町村区だけがエリアの選択肢に表示されます）。「検索する」ボタンをタップすると、検索結果の「掲載店舗」一覧まで自動的にスクロールします
- **プラチナプラン（トップページ表示枠）**：ホーム画面（1ページ目）の「掲載店舗」には、アドミンで「プラチナプラン契約店」にチェックを入れた店舗のみが、最大10件まで表示されます。プラチナプラン契約店が10件を超えて登録されている場合は、先頭10件のみが表示されます。1ページ目の一覧の最後には「全ての店舗情報を見る」ボタンが表示され、タップするとプラチナプラン以外の通常の店舗も含めた全店舗を閲覧できます。ただし、キーワード・エリア・業態で検索（人気エリア／業態アイコンのタップも含む）した場合は、この制限に関わらず、条件に一致するすべての店舗がそのまま1ページ目に表示されます
- **業態アイコン検索**：キャバクラ／ラウンジ／クラブ／ガールズバー／スナック／コンカフェ／ニュークラブ／ダイニングバー／その他をタップで絞り込み（アドミンの「業種の管理」で追加・名称変更・削除が可能）
- **人気エリアアイコン検索**：アドミンで登録したエリアがそのままアイコンとして表示されます（初期値：銀座・六本木・西麻布・新宿歌舞伎町・赤坂・渋谷・恵比寿・新橋・池袋）
- **現在地から探す**：ブラウザの位置情報を使って現在地から近い順に表示（店舗の緯度経度が未設定の場合はエリア名から自動推定）
- **店舗詳細ページ**：メイン写真1枚（大）＋サブ写真3枚（メイン写真の下に横長の長方形で横並び、3枚でぴったり幅いっぱいになるサイズ）のギャラリー（写真をタップするとポップアップで拡大表示）、店名・キャッチコピーの直下に**在籍キャスト紹介**、Instagram／TikTokアイコンリンク、住所（地図リンク付き）・営業時間・定休日、詳細文、予約・問い合わせボタン（電話／LINE／メール）
- **在籍キャストの管理（アドミン）**：店舗ごとにキャストの追加・編集・削除ができます（源氏名・一言コメントに加えて、丸いアイコンをクリックして顔写真も登録できます）
- **写真アップロード（アドミン）**：店舗ごとにメイン写真1枚＋サブ写真3枚（計4枚）を登録可能。クリックでファイル選択、またはドラッグ＆ドロップでアップロードできます（1枚目がメイン写真、2〜4枚目がメイン写真の下に横並びで表示されるサブ写真になります）
- **アドミン画面**：ログイン後、「店舗管理」タブに人気エリア・業種・エリア追加・タグの管理カードと、店舗の追加・編集・削除フォーム（都道府県、写真、住所、営業時間、定休日、SNS・LINEリンク、詳細文、タグ、在籍キャスト、緯度経度、プラチナプラン契約の有無など全項目を編集可能）がまとまっています。店舗登録フォームでは、まず都道府県を選ぶとエリアのチップ選択肢がその都道府県のものだけに絞り込まれます。「設定」タブには、ユーザー管理とサイト情報ページ（利用規約・運営会社情報）のみを配置しています。店舗一覧の上には、現在のプラチナプラン契約店の件数（◯／10件）が表示され、10件を超えるとその旨の注意表示が出ます
- **店舗一覧のページ送り（アドミン）**：加盟店（登録店舗）が増えてきた場合に備え、アドミンの店舗一覧に「表示件数」切り替え（10件／30件／50件）とページ送り（前へ・次へ）を用意しています。店舗一覧の行をタップすると、編集フォームの位置まで自動的にスクロールします
- **ユーザー管理（アドミン・設定タブ内）**：アドミン画面にログインできるアカウントを複数登録できます。ユーザー名とパスワードの組み合わせで追加・削除ができ（最低1人は必須）、ログイン中は画面右上に現在のユーザー名が表示され、ログアウトもできます
- **業種の管理（アドミン）**：業態アイコンの追加・名称変更・削除が可能。名称を変更すると、その業種が設定されている既存の店舗データも自動的に新しい名称に更新されます（未登録の業種にはアイコンが用意されていない場合、「その他」と同じ汎用アイコンが表示されます）
- **人気エリアの管理（アドミン）**：新しいエリアの追加・削除が可能。エリア名の入力欄の横で都道府県も選択して登録します（例：宮城県／仙台・国分町）。追加したエリアはホーム画面の「人気エリアから探す」（1ページ目のアイコン検索）と、その都道府県が選ばれたときの検索・店舗登録のエリア選択肢の両方に自動反映されます
- **エリア追加（アドミン）**：「人気エリアの管理」の下に用意した、通常エリアの追加・削除機能です（こちらも都道府県を選んで登録します）。ここに追加したエリアは検索・店舗登録時のエリア選択肢には反映されますが、ホーム画面の「人気エリアから探す」（1ページ目）には表示されません。人気エリアにしたくない一般的なエリアを増やしたいときに使います
- **店舗登録のエリア選択**：自由入力ではなく、登録済みの「人気エリア」「通常エリア」から選ぶ方式（アドミンで管理しているエリアと必ず紐付く仕組みです）。まず都道府県を選ぶと、その都道府県に登録されているエリアだけが横1行のチップ（ボタン）に表示され、左右にスクロールしてタップで選択します。実線のチップが人気エリア、点線のチップが通常エリアです
- **検索エンジンの都道府県→エリア連動**：ホーム画面の検索フォームでも同じ仕組みを採用しています。都道府県を選ぶとエリアの選択肢がその都道府県に登録されたエリアだけに絞り込まれるため、全国対応の店舗が増えても目的のエリアを探しやすくなっています
- **よく使うタグの管理（アドミン）**：「個室あり」「会員制」「カラオケあり」など、よく使うタグの候補をアドミンで追加・削除可能。店舗編集フォームでは候補をクリックするだけでタグの追加・削除ができます（自由入力欄も引き続き利用できます）
- **LINEで問い合わせるボタン**：店舗編集フォームで「LINE 相談先URL」を入力すると、詳細ページの「電話でご予約・お問い合わせ」ボタンの下に自動的に表示されます（未入力の店舗には表示されません）
- **利用規約・運営会社情報ページ（アドミンで編集）**：アドミン画面の「サイト情報ページ」カード内でタブを切り替えて編集します。「利用規約」タブでは本文を、「運営会社情報」タブでは会社名・代表者・所在地・電話番号・メールアドレス・設立・事業内容・備考を入力できます（特定商取引法に基づく表記などにご利用ください）。それぞれ「公開する」にチェックを入れて保存するとフッターにリンクが表示され、お客様が閲覧できるようになります。チェックを外すとリンクが消え、非公開に戻ります
- **コラム／ブログ／NEWS機能**：ヘッダーの「コラム」から記事一覧・記事詳細ページを閲覧できます。アドミン画面に「コラム管理」タブを新設し、記事ごとに以下を設定できます。
  - **URLスラッグ**：記事ごとに `#/column/スラッグ名` という個別のURLが発行されます（タイトル欄からフォーカスを外すと、タイトルから自動でスラッグ候補が入力されます。日本語タイトルの場合は `column-xxxxxx` のような自動生成スラッグになります）。同じスラッグを持つ記事は保存できないよう重複チェックがあります
  - **SEOタイトル／ディスクリプション**：未入力の場合は記事タイトル／抜粋がそのまま使われます。記事を開くとページタイトルとメタディスクリプションが自動的に書き換わります
  - **見出し・本文ブロック**：H2・H3の見出し、本文（段落）、画像、内部リンク（店舗詳細ページや他のコラム記事へのリンク）／外部リンク、ボタンを、ブロック単位で追加・削除・並び替え（↑↓）しながら記事を組み立てられます（H1にあたる記事タイトルは自動的に見出しとして表示されます）
  - **下書き・公開・予約投稿**：ステータスを「下書き」「公開」「予約投稿」から選択できます。予約投稿では公開日時を指定でき、その日時を過ぎると自動的に公開状態として一覧・個別ページに表示されます（サーバー側のバッチ処理ではなく、記事を表示する際にその都度、現在時刻と比較して判定する仕組みです）
  - **注意（重要）**：下記の「記事の静的HTML書き出し」機能を使わない場合、記事ごとのURLはブラウザ内のハッシュ（`#/column/...`）によるページ切り替えのみで実現されます。この方式だけでは、検索エンジンがこの1ページ内の個々の記事を正しく認識・評価できない場合があります。本格的に検索流入を狙う場合は、必ず下記の「記事の静的HTML書き出し」機能を使い、記事ごとに実際の（本物の）HTMLファイルを発行してください
- **SEO対策：記事の静的HTML書き出し（本物のクロール可能URLを発行）**：「コラム管理」タブに、公開中の記事を実際に独立したHTMLファイルとして書き出せる機能があります（WordPressのように、記事ごとに本当に別々のURLでアクセスできるようにするための機能です）。
  - 記事一覧の各行にある「静的HTML書き出し」ボタンを押すと、その記事1件分のHTMLファイル（例：`ginza-guide.html`）がダウンロードされます。「📦 公開中の記事をすべて書き出す（一覧ページ付き）」ボタンを押すと、公開中の全記事のHTMLファイルと、記事一覧ページ（`index.html`）がまとめてダウンロードされます
  - ダウンロードしたファイルは、`index.html`と同じ場所に新しく作った「`column`」というフォルダの中にアップロードしてください（GitHub Pagesの場合は、リポジトリに`column`フォルダを作り、その中にアップロードします）。アップロード後は `https://あなたのサイト/column/ginza-guide.html` のように、記事ごとに本物の個別URLでアクセスできるようになります
  - 書き出されたHTMLファイルは、タイトル・メタディスクリプション・本文がすべて最初からファイルの中に書き込まれた「完全に独立したページ」です。JavaScriptアプリの読み込みを待たずに検索エンジンが内容を読み取れるため、ハッシュURLだけの場合よりも正確にインデックスされやすくなります
  - 下書き状態の記事を書き出した場合は、誤って検索結果に表示されないよう、自動的に「noindex」（検索エンジンにインデックスさせない）設定つきで書き出されます
  - **この書き出しは自動更新されません**。記事を追加・編集・削除するたびに、もう一度書き出しボタンを押してファイルをダウンロードし直し、同じ場所に上書きアップロードする必要があります（WordPressのようにサーバーが自動的にページを生成する仕組みではないためです）
  - 「設定」タブの「SEO設定」で、サイトの公開URL（例：`https://ユーザー名.github.io/リポジトリ名/`）を設定しておくと、書き出したHTMLファイルと、コラム記事のハッシュURLページの両方に、正しいcanonical（正規URL）タグが自動的に入るようになります。未設定のままでも動作しますが、canonicalタグは発行されません

## データの保存について（重要）

店舗データの保存先は実行環境によって自動的に切り替わります。

- **Claude Artifacts 上で開いた場合**：Claude の共有データベース機能（`db` capability）を使用します。店舗ごとに1件のドキュメントとして保存され、誰が編集しても閲覧者全員に同じ内容が反映されます。1店舗あたりの保存容量には上限（約256KB）があるため、写真は自動的に小さく圧縮されます。
- **GitHub Pages などスタンドアロンで公開した場合**：ブラウザの `localStorage` を使用します。この場合、**編集内容はその端末・ブラウザだけに保存され、他の訪問者には共有されません**。全員に同じ店舗データを見せたい場合は、店舗データをサーバー（データベースやHeadless CMS、Firebase、Supabaseなど）に置き換える改修が必要です。`localStorage` は一般的に1ドメインあたり5〜10MB程度までという制限があります。

アップロードした写真は、ブラウザ内で自動的に縮小・圧縮した上でデータの中に直接埋め込んで保存しています（外部の画像サーバーは使用していません）。多数の店舗・高画質の写真を扱う本格運用では、画像を外部のストレージ（例：Cloudinary、S3、Firebase Storageなど）にアップロードし、そのURLだけを保存する方式への改修をおすすめします。

## カスタマイズのヒント

- 店舗の初期データは `index.html` の `DEFAULT_STORES` 配列にあります（`photos` 配列に写真、`casts` 配列に在籍キャスト情報を格納します）
- 写真の最大枚数や縮小サイズは `processPhotoFile` 関数内（`attempts` 配列の解像度・JPEG品質の値）で調整できます
- 配色・フォントは `<style>` 冒頭の `:root { --bg: ...; --terracotta: ...; }` などの変数から調整できます（現在は淡い水色のグラデーション×ゴールドの配色です。フッターのみ引き締め役として濃紺帯を残しています）
- 業態の一覧は `GENRE_LIST` 配列・`GENRE_ICONS` オブジェクトで変更できます
- 人気エリアの初期値は `DEFAULT_AREAS` 配列にあります（公開後はアドミン画面から追加・削除するのが基本です）
- よく使うタグの初期値は `DEFAULT_TAG_PRESETS` 配列にあります（公開後はアドミン画面から追加・削除できます）
- 予約ボタンは、電話番号が登録されていれば「電話でご予約・お問い合わせ」（tel:リンク）、なければメールでの問い合わせ（mailto:リンク）に自動的に切り替わります。LINE URLが登録されている場合は、その下に「LINEで来店相談」ボタンが追加で表示されます

# Night PASS — キャバクラ・ラウンジ紹介サイト

キャバクラ・ラウンジ・クラブ・ガールズバー・スナック・コンカフェなど、ナイトワーク系のお店を検索できるお客様向けの紹介サイトです（「GOOD TABLE」飲食店紹介サイトを基に、業界向けに作り直したものです）。

キーワード検索、業態／人気エリアのアイコン検索、現在地からの距離順検索、店舗詳細（写真・営業時間・SNSリンク・地図・在籍キャスト紹介）、店舗情報を編集できる管理（アドミン）画面を備えています。

## ファイル構成

```
.
├── index.html   サイト本体（HTML／CSS／JavaScriptを1ファイルに統合）
└── README.md         このファイル
```

HTML・CSS・JavaScriptをすべて `index.html` 1ファイルにまとめてあります。他のファイルへの参照がないため、この1ファイルだけをコピーすればどこでもそのまま動きます。

## 使い方（ローカル確認）

`index.html` をブラウザで直接開くだけで動作します。サーバーは不要です。

## GitHub Pages で公開する場合

`index.html` という名前になっているため、GitHub の新規リポジトリにそのままアップロードするだけで公開できます。

1. GitHub で新しいリポジトリを作成する（Public にしてください）
2. リポジトリ画面の **Add file → Upload files** を開き、`index.html` と `README.md` をドラッグ＆ドロップしてアップロードし、**Commit changes**
3. リポジトリの **Settings → Pages** を開く
4. **Branch** を `main`（または該当ブランチ）、フォルダを `/ (root)` に設定して **Save**
5. 数分後、`https://ユーザー名.github.io/リポジトリ名/` で公開されます（`index.html` はルートで自動的に表示されるページなので、URLの末尾にファイル名を付ける必要はありません）

## 主な機能

- **検索**：キーワード／都道府県／エリア／業態の4項目で絞り込み、セット料金・新着・店名で並び替え。都道府県を選ぶと、エリアの選択肢がその都道府県に登録されているエリア（市町村区）だけに自動的に絞り込まれます（例：「宮城県」を選ぶと、宮城県内で登録した市町村区だけがエリアの選択肢に表示されます）。「検索する」ボタンをタップすると、検索結果の「掲載店舗」一覧まで自動的にスクロールします
- **プラチナプラン（トップページ表示枠）**：ホーム画面（1ページ目）の「掲載店舗」には、アドミンで「プラチナプラン契約店」にチェックを入れた店舗のみが、最大10件まで表示されます。プラチナプラン契約店が10件を超えて登録されている場合は、先頭10件のみが表示されます。1ページ目の一覧の最後には「全ての店舗情報を見る」ボタンが表示され、タップするとプラチナプラン以外の通常の店舗も含めた全店舗を閲覧できます。ただし、キーワード・エリア・業態で検索（人気エリア／業態アイコンのタップも含む）した場合は、この制限に関わらず、条件に一致するすべての店舗がそのまま1ページ目に表示されます
- **業態アイコン検索**：キャバクラ／ラウンジ／クラブ／ガールズバー／スナック／コンカフェ／ニュークラブ／ダイニングバー／その他をタップで絞り込み（アドミンの「業種の管理」で追加・名称変更・削除が可能）
- **人気エリアアイコン検索**：アドミンで登録したエリアがそのままアイコンとして表示されます（初期値：銀座・六本木・西麻布・新宿歌舞伎町・赤坂・渋谷・恵比寿・新橋・池袋）
- **現在地から探す**：ブラウザの位置情報を使って現在地から近い順に表示（店舗の緯度経度が未設定の場合はエリア名から自動推定）
- **店舗詳細ページ**：メイン写真1枚（大）＋サブ写真3枚（メイン写真の下に横長の長方形で横並び、3枚でぴったり幅いっぱいになるサイズ）のギャラリー（写真をタップするとポップアップで拡大表示）、店名・キャッチコピーの直下に**在籍キャスト紹介**、Instagram／TikTokアイコンリンク、住所（地図リンク付き）・営業時間・定休日、詳細文、予約・問い合わせボタン（電話／LINE／メール）
- **在籍キャストの管理（アドミン）**：店舗ごとにキャストの追加・編集・削除ができます（源氏名・一言コメントに加えて、丸いアイコンをクリックして顔写真も登録できます）
- **写真アップロード（アドミン）**：店舗ごとにメイン写真1枚＋サブ写真3枚（計4枚）を登録可能。クリックでファイル選択、またはドラッグ＆ドロップでアップロードできます（1枚目がメイン写真、2〜4枚目がメイン写真の下に横並びで表示されるサブ写真になります）
- **アドミン画面**：ログイン後、「店舗管理」タブに人気エリア・業種・エリア追加・タグの管理カードと、店舗の追加・編集・削除フォーム（都道府県、写真、住所、営業時間、定休日、SNS・LINEリンク、詳細文、タグ、在籍キャスト、緯度経度、プラチナプラン契約の有無など全項目を編集可能）がまとまっています。店舗登録フォームでは、まず都道府県を選ぶとエリアのチップ選択肢がその都道府県のものだけに絞り込まれます。「設定」タブには、ユーザー管理とサイト情報ページ（利用規約・運営会社情報）のみを配置しています。店舗一覧の上には、現在のプラチナプラン契約店の件数（◯／10件）が表示され、10件を超えるとその旨の注意表示が出ます
- **店舗一覧のページ送り（アドミン）**：加盟店（登録店舗）が増えてきた場合に備え、アドミンの店舗一覧に「表示件数」切り替え（10件／30件／50件）とページ送り（前へ・次へ）を用意しています。店舗一覧の行をタップすると、編集フォームの位置まで自動的にスクロールします
- **ユーザー管理（アドミン・設定タブ内）**：アドミン画面にログインできるアカウントを複数登録できます。ユーザー名とパスワードの組み合わせで追加・削除ができ（最低1人は必須）、ログイン中は画面右上に現在のユーザー名が表示され、ログアウトもできます
- **業種の管理（アドミン）**：業態アイコンの追加・名称変更・削除が可能。名称を変更すると、その業種が設定されている既存の店舗データも自動的に新しい名称に更新されます（未登録の業種にはアイコンが用意されていない場合、「その他」と同じ汎用アイコンが表示されます）
- **人気エリアの管理（アドミン）**：新しいエリアの追加・削除が可能。エリア名の入力欄の横で都道府県も選択して登録します（例：宮城県／仙台・国分町）。追加したエリアはホーム画面の「人気エリアから探す」（1ページ目のアイコン検索）と、その都道府県が選ばれたときの検索・店舗登録のエリア選択肢の両方に自動反映されます
- **エリア追加（アドミン）**：「人気エリアの管理」の下に用意した、通常エリアの追加・削除機能です（こちらも都道府県を選んで登録します）。ここに追加したエリアは検索・店舗登録時のエリア選択肢には反映されますが、ホーム画面の「人気エリアから探す」（1ページ目）には表示されません。人気エリアにしたくない一般的なエリアを増やしたいときに使います
- **店舗登録のエリア選択**：自由入力ではなく、登録済みの「人気エリア」「通常エリア」から選ぶ方式（アドミンで管理しているエリアと必ず紐付く仕組みです）。まず都道府県を選ぶと、その都道府県に登録されているエリアだけが横1行のチップ（ボタン）に表示され、左右にスクロールしてタップで選択します。実線のチップが人気エリア、点線のチップが通常エリアです
- **検索エンジンの都道府県→エリア連動**：ホーム画面の検索フォームでも同じ仕組みを採用しています。都道府県を選ぶとエリアの選択肢がその都道府県に登録されたエリアだけに絞り込まれるため、全国対応の店舗が増えても目的のエリアを探しやすくなっています

- **利用規約・運営会社情報ページ（アドミンで編集）**：アドミン画面の「サイト情報ページ」カード内でタブを切り替えて編集します。「利用規約」タブでは本文を、「運営会社情報」タブでは会社名・代表者・所在地・電話番号・メールアドレス・設立・事業内容・備考を入力できます（特定商取引法に基づく表記などにご利用ください）。それぞれ「公開する」にチェックを入れて保存するとフッターにリンクが表示され、お客様が閲覧できるようになります。チェックを外すとリンクが消え、非公開に戻ります

  - **SEOタイトル／ディスクリプション**：未入力の場合は記事タイトル／抜粋がそのまま使われます。記事を開くとページタイトルとメタディスクリプションが自動的に書き換わります
  - **見出し・本文ブロック**：H2・H3の見出し、本文（段落）、画像、内部リンク（店舗詳細ページや他のコラム記事へのリンク）／外部リンク、ボタンを、ブロック単位で追加・削除・並び替え（↑↓）しながら記事を組み立てられます（H1にあたる記事タイトルは自動的に見出しとして表示されます）

  - 書き出されたHTMLファイルは、タイトル・メタディスクリプション・本文がすべて最初からファイルの中に書き込まれた「完全に独立したページ」です。JavaScriptアプリの読み込みを待たずに検索エンジンが内容を読み取れるため、ハッシュURLだけの場合よりも正確にインデックスされやすくなります
  - 下書き状態の記事を書き出した場合は、誤って検索結果に表示されないよう、自動的に「noindex」（検索エンジンにインデックスさせない）設定つきで書き出されます
  - **この書き出しは自動更新されません**。記事を追加・編集・削除するたびに、もう一度書き出しボタンを押してファイルをダウンロードし直し、同じ場所に上書きアップロードする必要があります（WordPressのようにサーバーが自動的にページを生成する仕組みではないためです）
  - 「設定」タブの「SEO設定」で、サイトの公開URL（例：`https://ユーザー名.github.io/リポジトリ名/`）を設定しておくと、書き出したHTMLファイルと、コラム記事のハッシュURLページの両方に、正しいcanonical（正規URL）タグが自動的に入るようになります。未設定のままでも動作しますが、canonicalタグは発行されません

## データの保存について（重要）

店舗データの保存先は実行環境によって自動的に切り替わります。

- **Claude Artifacts 上で開いた場合**：Claude の共有データベース機能（`db` capability）を使用します。店舗ごとに1件のドキュメントとして保存され、誰が編集しても閲覧者全員に同じ内容が反映されます。1店舗あたりの保存容量には上限（約256KB）があるため、写真は自動的に小さく圧縮されます。
- **GitHub Pages などスタンドアロンで公開した場合**：ブラウザの `localStorage` を使用します。この場合、**編集内容はその端末・ブラウザだけに保存され、他の訪問者には共有されません**。全員に同じ店舗データを見せたい場合は、店舗データをサーバー（データベースやHeadless CMS、Firebase、Supabaseなど）に置き換える改修が必要です。`localStorage` は一般的に1ドメインあたり5〜10MB程度までという制限があります。

アップロードした写真は、ブラウザ内で自動的に縮小・圧縮した上でデータの中に直接埋め込んで保存しています（外部の画像サーバーは使用していません）。多数の店舗・高画質の写真を扱う本格運用では、画像を外部のストレージ（例：Cloudinary、S3、Firebase Storageなど）にアップロードし、そのURLだけを保存する方式への改修をおすすめします。
